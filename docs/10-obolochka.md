# 10. Командная оболочка

Файл: [`kernel/shell.c`](../kernel/shell.c)

## 10.1. Что такое оболочка

**Оболочка** (shell) — программа, через которую человек управляет компьютером: принимает команды
и вызывает соответствующие функции ОС. Примеры: `bash` в Linux, `cmd.exe` и PowerShell в Windows.
Графический рабочий стол — тоже оболочка, только графическая.

Работа любой командной оболочки — бесконечный цикл **REPL** (Read — Eval — Print — Loop):

```c
void shell_run(void) {
    for (;;) {
        kprintf("minios> ");              // приглашение
        read_line(line, MAX_LINE);         // READ: прочитать строку
        argc = parse(line, argv);          // разбить на слова
        cmd = найти argv[0] в таблице;     // EVAL: найти команду
        cmd->fn(argc, argv);               // выполнить (она сама печатает — PRINT)
    }                                      // LOOP
}
```

## 10.2. Чтение строки

`read_line` получает символы по одному от драйвера клавиатуры (`keyboard_getchar`) и:

* обычный символ — добавляет в буфер и **показывает на экране** («эхо»: клавиатура сама ничего
  не выводит, это делает программа);
* `\b` (Backspace) — удаляет последний символ из буфера и с экрана;
* `\n` (Enter) — завершает ввод.

## 10.3. Разбор строки на аргументы

Строка `write note.txt Hello world` превращается в массив слов — как `argc/argv` в `main()`
обычной программы на C:

```
 исходная строка:  w r i t e ␣ n o t e . t x t ␣ H e l l o ␣ w o r l d \0
 после parse():    w r i t e \0 n o t e . t x t \0 H e l l o \0 w o r l d \0
                   ▲            ▲                   ▲            ▲
 argv[0] ──────────┘  argv[1] ──┘        argv[2] ───┘  argv[3] ───┘     argc = 4
```

Пробелы заменяются нулями прямо в строке, а `argv[i]` указывают на начала слов — никакого
копирования. Для команд `echo`, `write`, `append`, которым нужен текст с пробелами, оболочка
хранит копию исходной строки и берёт из неё «всё после N-го слова» (`rest_of_line`).

## 10.4. Таблица команд

Команды хранятся в таблице «имя → функция»:

```c
static const struct command commands[] = {
    { "help",  "show this list of commands",  cmd_help  },
    { "ls",    "list files",                  cmd_ls    },
    { "run",   "run <counter|spinner|clock>", cmd_run   },
    ...
};
```

Поиск — простой перебор с `strcmp`. Каждая команда — функция с сигнатурой `void fn(int argc, char **argv)`.

### Как добавить свою команду

Например, команду `hello`, которая здоровается по имени:

1. Напишите функцию в `shell.c` (перед таблицей `commands`):
   ```c
   static void cmd_hello(int argc, char **argv) {
       if (argc < 2) { kprintf("Usage: hello <name>\n"); return; }
       kprintf("Hello, %s!\n", argv[1]);
   }
   ```
2. Добавьте строку в таблицу:
   ```c
   { "hello", "hello <name> - greet someone", cmd_hello },
   ```
3. `make run` и введите `hello Student`.

## 10.5. Все команды и какую подсистему они демонстрируют

| Команда | Подсистема | Что происходит внутри |
|---|---|---|
| `help` | оболочка | перебор таблицы `commands` |
| `clear` | драйвер экрана | заполнение видеопамяти пробелами |
| `echo <текст>` | экран | `kprintf` → `vga_putc` → запись в `0xB8000` |
| `info` | всё | карта памяти, объём ОЗУ из CMOS, размер ядра (символ `__kernel_end` из linker.ld) |
| `mem` | менеджер памяти | обход списка блоков кучи |
| `date` | драйвер RTC | чтение ячеек CMOS через порты `0x70`/`0x71` |
| `uptime` | таймер | `ticks / 100` |
| `sleep <мс>` | таймер | ожидание `hlt` до нужного числа тиков |
| `ps` | планировщик | перебор массива `tasks` |
| `run <задача>` | планировщик, память | `task_create`: `kmalloc` стека + подделка регистров |
| `kill <id>` | планировщик | состояние задачи → `DEAD`, планировщик её больше не выберет |
| `ls`, `cat`, `write`, `append`, `rm` | файловая система | операции над таблицей `files` |
| `calc a op b` | — | разбор чисел `atoi`, проверка деления на ноль |
| `crash` | прерывания | деление на ноль → исключение #0 → kernel panic |
| `reboot` | порты | команда `0xFE` контроллеру клавиатуры `0x64` дёргает линию сброса процессора |
| `halt` | порты, ACPI | запись `0x2000` в порт `0x604` выключает виртуальную машину QEMU |

## 10.6. Чем оболочка MiniOS отличается от настоящей

В MiniOS оболочка — часть ядра и вызывает его функции напрямую. В настоящих ОС оболочка — обычная
программа в **пользовательском режиме** (кольцо 3). Она не может вызвать функцию ядра — у неё нет
доступа к его памяти. Вместо этого она делает **системный вызов** (system call):

```
  bash (кольцо 3)                       ядро Linux (кольцо 0)
  ───────────────                       ─────────────────────
  write(1, "hi", 2)
     │ кладёт номер вызова (1 = write)
     │ и аргументы в регистры
     │ syscall / int 0x80  ───────────► обработчик системных вызовов:
     │                                  проверяет аргументы,
     │                                  вызывает драйвер терминала
     │ ◄─────────────────── sysret/iret  возвращает результат в RAX
  продолжает работу
```

Системный вызов — это контролируемый «вход» в ядро через прерывание: программа не может прыгнуть
в произвольное место ядра, только в обработчик, который ядро само указало в IDT. Так ядро
защищает себя и другие программы.

Кроме того, настоящая оболочка запускает программы **из файлов** (`fork` + `exec` в Unix,
`CreateProcess` в Windows), поддерживает перенаправление ввода-вывода (`>`, `|`), переменные, скрипты.
