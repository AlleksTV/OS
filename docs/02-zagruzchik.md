# 2. Загрузчик: от включения питания до ядра

Файл: [`boot/boot.asm`](../boot/boot.asm)

## 2.1. Что делает компьютер при включении

1. После подачи питания процессор x86 сбрасывается и начинает выполнять команды с фиксированного
   адреса `0xFFFFFFF0`. Там находится **прошивка материнской платы — BIOS** (на современных ПК — UEFI,
   но он умеет имитировать BIOS; QEMU по умолчанию использует BIOS SeaBIOS).
2. BIOS выполняет самотестирование (**POST** — Power-On Self Test), инициализирует оборудование.
3. BIOS по порядку перебирает устройства (диск, флешку, CD) и у каждого читает **первый сектор** — 512 байт.
4. Если последние два байта сектора равны `0x55 0xAA` (**загрузочная подпись**), BIOS считает
   диск загрузочным, копирует сектор в память по адресу **`0x7C00`** и прыгает туда.

С этого момента управление у нас. Этот первый сектор называется **MBR** (Master Boot Record),
а программа в нём — **загрузчиком** (bootloader).

> Почему именно `0x7C00`? Историческое решение IBM PC 1981 года: загрузчик положили почти в конец
> первых 32 КБ памяти, чтобы оставить место ОС. Все BIOS с тех пор делают так же ради совместимости.

## 2.2. Реальный режим процессора

После включения процессор работает в **реальном режиме** (real mode) — режиме совместимости с
процессором Intel 8086 1978 года:

* регистры 16-битные (`AX`, `BX`, `SP`...), значит, одно число — максимум 65535;
* доступен только 1 МБ памяти;
* нет никакой защиты: любая программа может писать куда угодно;
* зато работают **функции BIOS**, вызываемые командой `int`: вывод на экран (`int 0x10`),
  чтение диска (`int 0x13`), работа с памятью (`int 0x15`).

### Сегментная адресация

Как 16-битными регистрами адресовать 1 МБ (20 бит)? Адрес складывается из двух частей:

```
физический адрес = сегмент × 16 + смещение
```

Например, `0x1000:0x0000` → `0x1000 × 16 + 0 = 0x10000`. Именно так мы указываем BIOS,
куда класть ядро: сегмент `0x1000`, смещение `0`.

## 2.3. Разбор загрузчика по шагам

### Шаг 0. Подготовка

```nasm
[org 0x7C00]        ; Сообщаем ассемблеру, что код будет лежать с адреса 0x7C00
[bits 16]           ; Генерировать 16-битный код

start:
    cli             ; Запретить прерывания на время настройки
    xor  ax, ax
    mov  ds, ax     ; Обнуляем сегментные регистры
    mov  es, ax
    mov  ss, ax
    mov  sp, 0x7C00 ; Стек растёт вниз от начала загрузчика
    sti
    mov  [boot_drive], dl   ; BIOS сообщает номер диска в регистре DL
```

**Стек** — область памяти, куда процессор складывает адреса возврата при вызове процедур (`call`)
и сохранённые значения (`push`). Стек на x86 растёт **вниз**: каждый `push` уменьшает `SP`.
Мы ставим стек под загрузчиком — там свободная память.

### Шаг 1. Чтение ядра с диска

Ядро лежит на диске сразу после загрузчика, начиная с сектора 1.
Для чтения используется функция BIOS **`int 0x13`, `AH = 0x42`** («расширенное чтение»).
Ей передаётся структура **DAP** (Disk Address Packet): сколько секторов, куда в память, откуда с диска.

```nasm
    mov  cx, KERNEL_SECTORS     ; сколько секторов читать
.read_loop:
    mov  si, disk_packet        ; адрес структуры-запроса
    mov  ah, 0x42
    mov  dl, [boot_drive]
    int  0x13                   ; ← BIOS читает 1 сектор
    jc   disk_error             ; флаг переноса CF = 1 → ошибка
    add  word [dap_segment], 0x20   ; следующий сектор — на 512 байт дальше
    add  dword [dap_lba], 1         ; следующий номер сектора
    loop .read_loop
```

Число `KERNEL_SECTORS` подставляет `Makefile`: он узнаёт размер собранного ядра и делит на 512
с округлением вверх.

**LBA** (Logical Block Addressing) — сквозная нумерация секторов: 0, 1, 2, ...
Раньше использовалась адресация **CHS** (цилиндр–головка–сектор), привязанная к геометрии диска;
она сложнее и ограничена 8 ГБ.

### Шаг 2. Линия A20

У процессора 8086 было 20 адресных линий (A0–A19), и адрес выше 1 МБ «заворачивался» в начало памяти.
Некоторые старые программы на это рассчитывали, поэтому в IBM PC/AT 21-ю линию (**A20**) по умолчанию
отключили. Чтобы пользоваться памятью выше 1 МБ (а наша куча начинается именно там), её нужно включить:

```nasm
    mov  ax, 0x2401     ; способ 1: попросить BIOS
    int  0x15
    in   al, 0x92       ; способ 2: «быстрый A20» через системный порт 0x92
    or   al, 2
    and  al, 0xFE       ; бит 0 трогать нельзя — он перезагружает компьютер!
    out  0x92, al
```

### Шаг 3. Переход в защищённый режим

Подробно — в [следующей главе](03-zashchishchennyj-rezhim.md). Кратко:

```nasm
    cli                         ; прерывания BIOS в новом режиме не работают
    lgdt [gdt_descriptor]       ; загрузить таблицу сегментов
    mov  eax, cr0
    or   eax, 1                 ; включить бит PE (Protection Enable)
    mov  cr0, eax
    jmp  CODE_SEG:protected_mode_start   ; дальний прыжок → 32-битный код
```

### Шаг 4. Прыжок в ядро

```nasm
[bits 32]
protected_mode_start:
    mov  ax, DATA_SEG   ; загрузить сегментные регистры данных
    mov  ds, ax
    ...
    mov  esp, 0x90000   ; новый стек
    jmp  0x10000        ; → ядро (kernel/entry.asm)
```

### Подпись

```nasm
times 510 - ($ - $$) db 0   ; дополнить нулями до 510 байт
dw 0xAA55                   ; байты 0x55, 0xAA (x86 хранит числа «младшим байтом вперёд»)
```

## 2.4. Образ диска

`Makefile` склеивает загрузчик и ядро в один файл — образ диска `build/os.img`:

```
 сектор 0         сектор 1 ... сектор N
┌───────────┬──────────────────────────────┬─────────────────────┐
│ boot.bin  │         kernel.bin           │  нули (до 1 МБ)     │
│ 512 байт  │       ~16 КБ (≈31 сектор)    │                     │
└───────────┴──────────────────────────────┴─────────────────────┘
```

QEMU воспринимает этот файл как жёсткий диск. Если записать его на флешку
(`dd if=build/os.img of=/dev/sdX`), с неё можно загрузить реальный компьютер с поддержкой
Legacy BIOS / CSM.

## 2.5. Как это сделано в настоящих ОС

512 байт слишком мало для серьёзного загрузчика, поэтому реальные загрузчики (GRUB, Windows Boot Manager)
работают в несколько **стадий**: MBR загружает вторую стадию побольше, та умеет читать файловую
систему, показывать меню, загружать ядро из файла. На компьютерах с **UEFI** всё иначе: прошивка
сама умеет читать раздел FAT32 и запускает загрузчик как обычный файл `.efi`, сразу в 32/64-битном режиме.
