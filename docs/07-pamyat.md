# 7. Управление памятью

Файл: [`kernel/memory.c`](../kernel/memory.c)

## 7.1. Зачем нужен менеджер памяти

Часть памяти распределяется заранее, ещё при компиляции: код ядра, глобальные переменные,
таблица файлов. Но многое заранее неизвестно:

* сколько задач запустит пользователь — каждой нужен свой стек 4 КБ;
* сколько файлов он создаст и какого размера.

Для этого существует **динамическая память**: область, из которой куски выдаются по запросу
и возвращаются, когда больше не нужны. Эта область называется **кучей** (heap), а функции —
`kmalloc(размер)` и `kfree(указатель)` (в обычных программах — `malloc` и `free`).

В MiniOS куча занимает 4 МБ, начиная с адреса `0x100000` (1 МБ) — сразу за областью BIOS и видеопамяти.

## 7.2. Устройство кучи: список блоков

Куча разбита на **блоки**. Перед каждым блоком лежит маленький **заголовок**:

```c
struct block {
    uint32_t size;          // размер данных блока
    uint32_t free;          // 1 — свободен, 0 — занят
    struct block *next;     // следующий блок
    uint32_t magic;         // «подпись» 0xC0FFEE42 для проверки
};
```

Блоки идут подряд и образуют **связный список**:

```
 0x100000
 ┌────────┬────────────┬────────┬──────────┬────────┬─────────────────────────┐
 │заголов.│ данные     │заголов.│ данные    │заголов.│                         │
 │216, 0  │ readme.txt │16, 0   │ hello.txt │ 4 МБ,1 │      свободно ...       │
 │ next ──┼────────────┼─►      │           │        │                         │
 └────────┴────────────┴────────┴──────────┴────────┴─────────────────────────┘
            ▲
            └── kmalloc возвращает адрес ПОСЛЕ заголовка
```

Сразу после `memory_init()` вся куча — один большой свободный блок.

## 7.3. Выделение: `kmalloc` — алгоритм «первый подходящий»

```c
void *kmalloc(size_t size) {
    size = (size + 7) & ~7;                    // округлить до 8 байт
    for (b = heap_head; b; b = b->next) {
        if (!b->free || b->size < size) continue;   // не подходит — дальше
        if (b->size >= size + HEADER_SIZE + 16)      // слишком большой —
            разрезать на два: [занятый size] [свободный остаток]
        b->free = 0;
        return (uint8_t *)b + HEADER_SIZE;
    }
    return NULL;                               // памяти нет
}
```

Это алгоритм **first-fit** («первый подходящий»). Есть и другие:

| Алгоритм | Как выбирает блок | Плюсы и минусы |
|---|---|---|
| First-fit | первый достаточно большой | быстро, но в начале кучи копится мелочь |
| Best-fit | самый маленький из подходящих | меньше потерь, но надо просмотреть весь список |
| Worst-fit | самый большой | остатки крупнее, но быстро «съедает» большие блоки |
| Buddy | блоки размером степени двойки, делятся пополам | быстро и мало фрагментации; используется в Linux для страниц |

Размер округляется до 8 байт, чтобы данные были **выровнены**: процессор быстрее работает с числами,
лежащими по адресам, кратным их размеру.

## 7.4. Освобождение: `kfree` и фрагментация

`kfree(p)` находит заголовок (он лежит прямо перед `p`), проверяет подпись `magic` и помечает блок
свободным. Затем **склеивает соседние свободные блоки**.

Зачем склеивать? Представьте: выделили A, B, C по 100 байт, потом освободили A и B.
Без склейки в куче два свободных блока по 100 байт, и запрос на 150 байт не выполнится, хотя
свободно 200. Это называется **фрагментацией** — свободная память есть, но она разбита на куски.

```
 до kfree(B):  [A свободен 100][B занят 100][C занят 100][свободно ...]
 после:        [A+B свободен 208          ][C занят 100][свободно ...]
```

## 7.5. Посмотрите сами

Команда `mem` показывает список блоков. Запустите пару задач и посмотрите снова:

```
minios> run counter
minios> run spinner
minios> mem
  #   address     size       state
   0  0x00100010       216   USED      ← readme.txt
   1  0x001000F8        16   USED      ← hello.txt
   2  0x00100118      4096   USED      ← стек задачи clock
   3  0x00101128      4096   USED      ← стек counter
   4  0x00102138      4096   USED      ← стек spinner
   5  0x00103148   4177576   free
```

Попробуйте `write a.txt 111`, `write b.txt 222`, `rm a.txt`, `mem` — увидите свободную «дырку» посреди
занятых блоков, а затем как она переиспользуется при следующем `write`.

## 7.6. Защита: `irq_save` / `irq_restore`

Список блоков — общие данные. Если задача A находится посреди разрезания блока, а таймер переключит
процессор на задачу B, которая тоже вызовет `kmalloc`, — B увидит испорченный список. Поэтому
`kmalloc` и `kfree` выполняются с запрещёнными прерываниями: `irq_save()` сохраняет флаги и делает `cli`,
`irq_restore()` возвращает всё как было.

## 7.7. Как это сделано в настоящих ОС: виртуальная память

В MiniOS все задачи видят **одну и ту же физическую память**. Задача с ошибкой может испортить стек
другой задачи или само ядро. В настоящих ОС управление памятью устроено в два уровня:

1. **Менеджер физической памяти** раздаёт память **страницами** по 4 КБ (обычно с помощью битовой
   карты или buddy-алгоритма).
2. **Страничная адресация** (paging): процессор переводит каждый адрес, который использует программа
   (**виртуальный**), в **физический** по таблицам страниц, которые заполняет ОС.

```
 Программа A                Таблица страниц A           Физическая память
 вирт. 0x00400000 ─────────► страница № 0x12345 ────────► 0x12345000
 Программа B                Таблица страниц B
 вирт. 0x00400000 ─────────► страница № 0x0ABCD ────────► 0x0ABCD000
```

Что это даёт:

* **изоляция**: каждая программа имеет своё адресное пространство и физически не может обратиться
  к памяти другой программы или ядра;
* **одинаковые адреса**: все программы можно компилировать под один и тот же адрес;
* **подкачка** (swap): редко используемые страницы выгружаются на диск, а при обращении к ним
  возникает исключение Page Fault (#14), и ОС тихо подгружает их обратно;
* **общие библиотеки**: одна физическая копия библиотеки отображается во все программы.

Чтобы включить страничную адресацию в MiniOS, нужно создать таблицы страниц, записать адрес каталога
в регистр `CR3` и установить бит 31 (PG) регистра `CR0`.
