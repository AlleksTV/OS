# 6. Драйверы: таймер, часы, клавиатура

Файлы: [`kernel/timer.c`](../kernel/timer.c), [`kernel/keyboard.c`](../kernel/keyboard.c)

**Драйвер** — часть ОС, которая умеет работать с конкретным устройством и даёт остальной системе
простой интерфейс. Остальной код не знает про порты и скан-коды — он вызывает `keyboard_getchar()`
или `timer_ticks()`. Все драйверы MiniOS устроены по одной схеме:

1. функция инициализации `xxx_init()` настраивает устройство и регистрирует обработчик прерывания;
2. обработчик прерывания быстро забирает данные у устройства и сохраняет их;
3. функции интерфейса отдают сохранённые данные остальному ядру.

## 6.1. Системный таймер PIT

**PIT** (Programmable Interval Timer, микросхема Intel 8253/8254) — генератор импульсов с частотой
**1 193 182 Гц** (историческая частота, связанная с телевизионным стандартом NTSC). Записав в него
**делитель** N, получаем прерывание IRQ0 с частотой `1193182 / N` раз в секунду.

```c
#define TIMER_HZ 100
uint32_t divisor = 1193182 / TIMER_HZ;      // = 11931

outb(0x43, 0x36);                 // команда: канал 0, режим 3, младший+старший байт
outb(0x40, divisor & 0xFF);       // младший байт делителя
outb(0x40, divisor >> 8);         // старший байт делителя
```

Обработчик предельно прост:

```c
static volatile uint32_t ticks = 0;
static void timer_handler(struct regs *r) { ticks++; }
```

Слово **`volatile`** говорит компилятору: «эта переменная может измениться в любой момент сама по себе»
(в обработчике прерывания). Без него оптимизатор мог бы прочитать `ticks` один раз, положить в регистр,
и цикл ожидания `while (ticks < end)` стал бы бесконечным.

### Зачем ОС таймер

Таймер — «сердцебиение» системы. По его тикам:

* **считается время**: `uptime` = `ticks / 100` секунд (команда `uptime`, часы в правом верхнем углу);
* **работают задержки**: `sleep_ms(500)` ждёт, пока `ticks` не увеличится на 50;
* **переключаются задачи**: после каждого тика вызывается планировщик (глава 8).
  Без таймера вытесняющая многозадачность невозможна — задача, попавшая в бесконечный цикл,
  никогда не отдала бы процессор.

```c
void sleep_ms(uint32_t ms) {
    uint32_t end = ticks + ms * TIMER_HZ / 1000;
    while (ticks < end)
        hlt();          // спать до следующего прерывания
}
```

Команда **`hlt`** останавливает процессор до прихода прерывания. Это экономит энергию:
процессор не крутится впустую. Именно так ведут себя настоящие ОС в простое — поэтому ноутбук
без нагрузки почти не греется.

Точность таймера — 10 мс (один тик). Попробуйте `sleep 1000`.

## 6.2. Часы реального времени и CMOS

Таймер PIT считает время только с момента загрузки. Откуда ОС знает текущую дату?
На материнской плате есть микросхема **CMOS** с батарейкой. В ней:

* **RTC** (Real-Time Clock) — часы, которые идут даже при выключенном компьютере;
* настройки BIOS, в том числе **объём памяти**.

Доступ — через два порта: в `0x70` пишем номер ячейки, из `0x71` читаем значение.

| Ячейка | Содержимое |
|---|---|
| `0x00`, `0x02`, `0x04` | секунды, минуты, часы |
| `0x07`, `0x08`, `0x09` | день, месяц, год (две цифры) |
| `0x0A` | статус A: бит 7 = «идёт обновление, подождите» |
| `0x0B` | статус B: формат чисел (BCD/двоичный, 12/24 часа) |
| `0x30`/`0x31`, `0x34`/`0x35` | объём памяти выше 1 МБ и выше 16 МБ |

Часы обычно хранят числа в формате **BCD** (двоично-десятичном): `0x59` означает 59, а не 89.
Каждая половина байта — одна десятичная цифра. Перевод: `(v & 0x0F) + (v >> 4) * 10`.

Команда `date` показывает время из RTC, `info` — объём памяти из CMOS. Время QEMU показывает в UTC.

## 6.3. Клавиатура

### Скан-коды

Клавиатура не передаёт символы. Она передаёт **скан-коды** — номера клавиш.
Буква `A`, `a` и русская `Ф` — одна и та же клавиша и один скан-код `0x1E`. Какой символ ей
соответствует, решает ОС по **раскладке** и состоянию Shift/Caps Lock.

У каждой клавиши два кода:

* **make-код** при нажатии (`0x1E` для A);
* **break-код** при отпускании = make-код + `0x80` (`0x9E` для A).

Некоторые клавиши (стрелки, Home, End, правый Ctrl) посылают префикс `0xE0` и ещё один байт —
это «расширенные» коды. MiniOS их пропускает.

### Обработчик прерывания IRQ1

```c
static void keyboard_handler(struct regs *r) {
    uint8_t scancode = inb(0x60);              // прочитать скан-код
    if (scancode & 0x80) {                      // клавиша отпущена
        if (это Shift) shift_pressed = false;
        return;
    }
    if (это Shift)     { shift_pressed = true; return; }
    if (это CapsLock)  { caps_lock = !caps_lock; return; }
    char c = shift_pressed ? keymap_shift[scancode] : keymap[scancode];
    if (c) buffer_put(c);                       // в кольцевой буфер
}
```

Таблицы `keymap` и `keymap_shift` — это и есть **раскладка** (US QWERTY): индекс — скан-код, значение — символ.
Чтобы добавить русскую раскладку, понадобились бы ещё две таблицы, переключатель и шрифт с кириллицей.

### Кольцевой буфер

Прерывание приходит **когда угодно** — в том числе когда оболочка занята выполнением команды.
Символы нельзя терять, поэтому драйвер складывает их в **кольцевой буфер** (ring buffer),
а оболочка забирает, когда освободится:

```
          tail (отсюда читает оболочка)
           ▼
 ┌───┬───┬───┬───┬───┬───┬───┬───┐
 │   │   │ l │ s │ \n│   │   │   │     256 ячеек
 └───┴───┴───┴───┴───┴───┴───┴───┘
                       ▲
                      head (сюда пишет обработчик прерывания)

 head == tail            → буфер пуст
 (head + 1) % 256 == tail → буфер полон
```

Когда индекс доходит до конца массива, он «заворачивается» на начало (`% 256`) — отсюда название «кольцевой».
Это классическая схема **«производитель — потребитель»**: производитель (прерывание) только двигает `head`,
потребитель (оболочка) только двигает `tail`, поэтому им даже не нужна блокировка.

```c
char keyboard_getchar(void) {
    while (head == tail)    // буфер пуст —
        hlt();              // спим до следующего прерывания
    char c = buffer[tail];
    tail = (tail + 1) % BUFFER_SIZE;
    return c;
}
```

## 6.4. Полный путь нажатия клавиши

Что происходит, когда вы нажимаете `l` в оболочке MiniOS:

1. Контроллер клавиатуры кладёт скан-код `0x26` в порт `0x60` и подаёт сигнал на линию IRQ1.
2. PIC пересылает прерывание процессору как вектор 33.
3. Процессор сохраняет `EIP/CS/EFLAGS`, берёт из IDT[33] адрес `irq1` (isr.asm) и прыгает туда.
4. `irq1` кладёт в стек номер 33 и переходит в `isr_common`, которая сохраняет регистры и вызывает
   `interrupt_handler`.
5. `interrupt_handler` видит вектор 33 → IRQ1 → вызывает `keyboard_handler`.
6. `keyboard_handler` читает `0x26` из порта, находит в `keymap[0x26]` символ `'l'`, кладёт в буфер.
7. `interrupt_handler` посылает EOI в PIC.
8. `isr_common` восстанавливает регистры, `iret` возвращает процессор туда, где он был.
9. Оболочка, ожидавшая в `keyboard_getchar()` на команде `hlt`, просыпается, видит символ в буфере,
   забирает его и выводит на экран через `vga_putc('l')` — запись в видеопамять `0xB8000`.

Всё это занимает несколько микросекунд.
