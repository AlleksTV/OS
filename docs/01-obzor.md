# 1. Обзор: что такое операционная система и как устроена MiniOS

## 1.1. Зачем нужна операционная система

Компьютер «из коробки» — это процессор, память и устройства (экран, клавиатура, диск, таймер).
Процессор умеет только одно: брать из памяти команды и выполнять их по очереди.
Он ничего не знает о файлах, программах, окнах и пользователях.

**Операционная система (ОС)** — программа, которая запускается первой и:

1. **Управляет оборудованием.** Только ОС знает, как обращаться к клавиатуре, экрану, диску.
   Программы просят об этом ОС, а не работают с устройствами напрямую.
   Части ОС, которые работают с конкретными устройствами, называются **драйверами**.
2. **Распределяет ресурсы.** Процессор один, а программ много — ОС решает, кто и когда выполняется
   (**планировщик**). Память одна — ОС решает, кому какой кусок дать (**менеджер памяти**).
3. **Даёт удобные абстракции.** Вместо «сектор 2048 на диске» — «файл `report.txt`»
   (**файловая система**). Вместо «прерывание IRQ1, скан-код 0x1E» — «нажата буква a».
4. **Даёт интерфейс пользователю** — командную строку (**оболочку**) или графический рабочий стол.

Центральная часть ОС, которая работает с максимальными правами и управляет всем остальным, называется **ядром** (kernel).

## 1.2. Архитектура MiniOS

MiniOS устроена как настоящая ОС, только каждая подсистема упрощена до минимума.

```
 ┌──────────────────────────────────────────────────────────────────┐
 │                  ОБОЛОЧКА (shell.c)                              │
 │   help, ls, cat, run, ps, kill, mem, calc, date, reboot ...      │
 ├───────────────┬───────────────┬────────────────┬─────────────────┤
 │ Планировщик   │ Менеджер      │ Файловая       │ Фоновые задачи  │
 │ задач         │ памяти        │ система        │ (programs.c)    │
 │ (task.c)      │ (memory.c)    │ (fs.c)         │                 │
 ├───────────────┴───────────────┴────────────────┴─────────────────┤
 │           Подсистема прерываний (interrupts.c, isr.asm)          │
 ├──────────────┬──────────────────┬────────────────┬───────────────┤
 │ Драйвер      │ Драйвер          │ Драйвер        │ Библиотека    │
 │ экрана       │ клавиатуры       │ таймера/часов  │ (lib.c)       │
 │ (vga.c)      │ (keyboard.c)     │ (timer.c)      │               │
 ╞══════════════╧══════════════════╧════════════════╧═══════════════╡
 │ ОБОРУДОВАНИЕ: процессор x86, ОЗУ, видеокарта VGA, клавиатура,     │
 │ таймер PIT 8254, контроллер прерываний PIC 8259, часы CMOS/RTC   │
 └──────────────────────────────────────────────────────────────────┘
```

Нижние уровни ничего не знают о верхних. Например, драйвер клавиатуры просто складывает
символы в буфер, а оболочка их оттуда забирает. Такое разделение на слои — главный приём
при проектировании любой ОС.

MiniOS — это **монолитное ядро**: все подсистемы, включая оболочку, работают в одном адресном
пространстве с максимальными привилегиями (кольцо 0). Так же устроены Linux и старые версии Windows
(правда, у них оболочка работает отдельно, в пользовательском режиме).

## 1.3. Что происходит от включения до командной строки

```
 Включение питания
        │
        ▼
 ┌─────────────┐  Процессор начинает выполнять код прошивки BIOS (из ПЗУ).
 │    BIOS     │  BIOS проверяет оборудование (POST), ищет загрузочный диск
 └──────┬──────┘  и копирует его ПЕРВЫЙ СЕКТОР (512 байт) по адресу 0x7C00.
        │
        ▼
 ┌─────────────┐  boot/boot.asm — 16-битный реальный режим.
 │  ЗАГРУЗЧИК  │  1) читает ядро с диска в память по адресу 0x10000;
 │   (MBR)     │  2) включает линию A20;
 └──────┬──────┘  3) загружает GDT и переходит в 32-битный защищённый режим.
        │ jmp 0x10000
        ▼
 ┌─────────────┐  kernel/entry.asm: настраивает стек, обнуляет .bss,
 │ entry.asm   │  вызывает функцию kmain() на языке C.
 └──────┬──────┘
        ▼
 ┌─────────────┐  kernel/kernel.c — по очереди инициализирует подсистемы:
 │   kmain()   │  экран → прерывания → память → таймер → клавиатура →
 └──────┬──────┘  задачи → файловая система → sti (разрешить прерывания)
        ▼
 ┌─────────────┐  kernel/shell.c — бесконечный цикл:
 │   ОБОЛОЧКА  │  приглашение → ввод строки → выполнение команды → ...
 └─────────────┘  Параллельно таймер 100 раз в секунду переключает задачи.
```

Каждый шаг подробно разобран в следующих главах.

## 1.4. Карта памяти

Память компьютера — огромный массив байтов, каждый байт имеет номер — **адрес**.
MiniOS не использует виртуальную память, поэтому адреса в программе совпадают с физическими.
Вот как MiniOS распоряжается первыми мегабайтами (команда `info` показывает то же самое):

```
 Адрес          Что там лежит
 ─────────────────────────────────────────────────────────────────
 0x00000000  ┌──────────────────────────────────────┐
             │ Таблица прерываний BIOS и данные BIOS │  (нам не нужны после загрузки)
 0x00000500  ├──────────────────────────────────────┤
             │ свободно                             │
 0x00007C00  ├──────────────────────────────────────┤
             │ ЗАГРУЗЧИК (512 байт) + его стек ниже  │
 0x00007E00  ├──────────────────────────────────────┤
             │ свободно                             │
 0x00010000  ├──────────────────────────────────────┤
             │ ЯДРО: код (.text), константы          │  ≈ 20 КБ
             │ (.rodata), данные (.data, .bss)       │
             ├──────────────────────────────────────┤
             │ свободно                             │
             │            ▲ стек ядра растёт вниз   │
 0x00090000  ├──────────────────────────────────────┤  ← вершина стека ядра
             │ область BIOS (EBDA)                  │
 0x000A0000  ├──────────────────────────────────────┤
             │ видеопамять; 0xB8000 — текстовый      │
             │ экран 80×25                          │
 0x000C0000  ├──────────────────────────────────────┤
             │ ПЗУ BIOS и устройств                 │
 0x00100000  ├──────────────────────────────────────┤  ← 1 МБ
             │ КУЧА (4 МБ): kmalloc/kfree           │
             │ стеки задач, файлы ...               │
 0x00500000  ├──────────────────────────────────────┤
             │ свободно (до конца ОЗУ)              │
             └──────────────────────────────────────┘
```

## 1.5. Структура исходного кода

| Файл | Строк | Назначение |
|---|---|---|
| `boot/boot.asm` | 295 | Загрузчик: чтение ядра (LBA или CHS), A20, GDT, защищённый режим |
| `kernel/entry.asm` | 43 | Точка входа ядра, обнуление .bss |
| `kernel/linker.ld` | 46 | Где в памяти разместить ядро |
| `kernel/kernel.c` | 73 | `kmain()` — порядок инициализации |
| `kernel/isr.asm` | 148 | Обработчики прерываний на ассемблере, переключение стека |
| `kernel/interrupts.c` | 188 | IDT, PIC, диспетчер прерываний, kernel panic |
| `kernel/vga.c` | 129 | Вывод на экран, прокрутка, курсор, `kprintf` |
| `kernel/timer.c` | 100 | Таймер, `sleep_ms`, часы реального времени |
| `kernel/keyboard.c` | 128 | Клавиатура, раскладка, кольцевой буфер |
| `kernel/memory.c` | 116 | `kmalloc`/`kfree` |
| `kernel/task.c` | 149 | Задачи и планировщик |
| `kernel/fs.c` | 101 | Файловая система в памяти |
| `kernel/shell.c` | 334 | Командная оболочка |
| `kernel/lib.c` | 152 | `memcpy`, `strcmp`, `ksnprintf` и т.д. |
| `kernel/programs.c` | 71 | Демонстрационные фоновые задачи (часы, счётчик, вертушка) |

## 1.6. Почему ассемблер и C

* **Ассемблер** нужен там, где требуется прямой контроль над процессором:
  первые команды после включения, переход между режимами, сохранение всех регистров при прерывании.
  В языке C просто нет конструкций вроде «загрузить таблицу GDT» или «вернуться из прерывания».
* **C** используется для всего остального: на нём проще писать и читать логику.
  Так же устроены настоящие ОС: Linux, ядро Windows и macOS написаны в основном на C,
  с небольшими вставками на ассемблере.

Важная деталь: ядро **не может пользоваться стандартной библиотекой C** (`printf`, `malloc`, `strlen`...).
Эти функции сами обращаются к операционной системе, а ОС — это мы. Поэтому в `lib.c`, `vga.c` и `memory.c`
мы написали свои аналоги: `kprintf`, `kmalloc`, `strlen`.
