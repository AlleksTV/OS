# 4. Ядро: точка входа, компоновка, вывод на экран

Файлы: [`kernel/entry.asm`](../kernel/entry.asm), [`kernel/linker.ld`](../kernel/linker.ld),
[`kernel/kernel.c`](../kernel/kernel.c), [`kernel/vga.c`](../kernel/vga.c), [`kernel/ports.h`](../kernel/ports.h)

## 4.1. Как C-код превращается в ядро

Обычная программа на C компилируется в исполняемый файл (`.exe` в Windows, ELF в Linux), который
**загружает операционная система**: читает заголовки, раскладывает секции по памяти, подключает
библиотеки, вызывает `main`. У нас ОС ещё нет, а загрузчик умеет только одно — скопировать байты
с диска по адресу `0x10000` и прыгнуть на первый байт. Значит, нужно:

1. Скомпилировать C **без стандартной библиотеки** и без зависимостей от ОС:
   флаги `-ffreestanding -nostdlib -fno-builtin -fno-stack-protector`.
2. Объяснить компоновщику, что код будет работать **по адресу `0x10000`**, а **первой** должна идти
   точка входа `_start` — это делает скрипт `linker.ld`.
3. Превратить ELF-файл в «голый» машинный код без заголовков: `objcopy -O binary`.

```
 kernel.c ─┐
 vga.c ────┤ gcc -m32 -c    ┌──────────┐
 ...       ├──────────────► │  *.o     │──┐
 entry.asm ┤ nasm -f elf32  └──────────┘  │ ld -T linker.ld   ┌────────────┐ objcopy   ┌────────────┐
 isr.asm ──┘                              ├─────────────────► │ kernel.elf │─────────► │ kernel.bin │
                               linker.ld ─┘                   └────────────┘           └────────────┘
                                                              (для отладчика)          (на диск)
```

### Секции программы

Компилятор раскладывает программу по **секциям**:

| Секция | Что содержит | Пример |
|---|---|---|
| `.text` | машинный код | тела функций |
| `.rodata` | константы | строки `"help"`, таблица `keymap` |
| `.data` | глобальные переменные с начальным значением | `static int x = 5;` |
| `.bss` | глобальные переменные без значения (должны быть нулями) | `static struct task tasks[6];` |

Секция `.bss` не хранится в файле — зачем хранить килобайты нулей? Обычно её обнуляет загрузчик программ ОС,
а у нас — `entry.asm`.

## 4.2. Точка входа `entry.asm`

```nasm
_start:
    mov  esp, 0x90000       ; стек ядра
    mov  edi, __bss_start   ; обнулить .bss
    mov  ecx, __bss_end
    sub  ecx, edi
    xor  eax, eax
    rep  stosb              ; повторить ECX раз: [EDI++] = AL
    call kmain              ; → в C!
```

Символы `__bss_start` и `__bss_end` создаёт компоновщик по нашему скрипту `linker.ld` — это
адреса начала и конца секции `.bss` в памяти.

## 4.3. Главная функция `kmain`

`kmain` в `kernel.c` — это «`main` операционной системы». Она по очереди запускает подсистемы
и печатает журнал загрузки `[ OK ] ...`:

```c
void kmain(void) {
    vga_init();          // 1. экран — чтобы видеть, что происходит
    interrupts_init();   // 2. таблица прерываний + контроллер прерываний
    memory_init();       // 3. куча
    timer_init();        // 4. драйверы устройств
    keyboard_init();
    tasking_init();      // 5. многозадачность
    fs_init();           // 6. файловая система
    sti();               // 7. РАЗРЕШИТЬ прерывания
    task_create("clock", clock_task);
    shell_run();         // 8. оболочка — работает вечно
}
```

**Порядок важен.** Прерывания разрешаются (`sti`) только после того, как всё готово:
если таймер тикнет раньше, чем настроена таблица IDT, процессор прыгнет по случайному адресу.
Если раньше, чем настроен планировщик, — переключит задачи, которых ещё нет.

Функция `kmain` **никогда не возвращается**: возвращаться некуда, над ядром ничего нет.

## 4.4. Как ядро выводит текст: видеопамять

В BIOS был `int 0x10`, но в защищённом режиме он недоступен. Как же вывести символ?

Видеокарта в **текстовом режиме 80×25** постоянно читает область памяти, начинающуюся с адреса
**`0xB8000`**, и рисует по ней символы. Каждая клетка экрана — 2 байта:

```
 Адрес 0xB8000 + (y × 80 + x) × 2
 ┌──────────────────┬───────────────────────────────┐
 │  байт 0: символ   │ байт 1: атрибут (цвет)          │
 │  ASCII-код       │ ┌──────────┬───────────────┐  │
 │  'A' = 0x41      │ │ фон 4 бит │ символ 4 бита │  │
 │                  │ └──────────┴───────────────┘  │
 └──────────────────┴───────────────────────────────┘
```

Значит, чтобы вывести белую букву `A` на синем фоне в левый верхний угол, достаточно одной строки:

```c
*(uint16_t *)0xB8000 = 'A' | (0x1F << 8);   // 0x1F: фон 1 (синий), символ F (белый)
```

Никаких специальных команд — **обычная запись в память**. Такой способ общения с устройством
называется **ввод-вывод, отображённый в память** (memory-mapped I/O, MMIO).

Цвета: 0 чёрный, 1 синий, 2 зелёный, 3 голубой, 4 красный, 5 пурпурный, 6 коричневый, 7 светло-серый,
8–15 — те же, но яркие (14 жёлтый, 15 белый).

### Что делает драйвер `vga.c`

* хранит позицию курсора `cursor_x`, `cursor_y` и текущий цвет;
* `vga_putc(c)` пишет символ в видеопамять и сдвигает курсор, обрабатывая `\n`, `\b` (backspace), `\t`;
* когда курсор уходит за нижний край — **прокрутка**: `memmove` строк 2..24 на место 1..23
  и очистка последней строки (прокрутка — это просто копирование памяти!);
* верхняя строка 0 — **строка состояния**: её не трогают ни прокрутка, ни очистка; в неё пишут фоновые задачи
  через `vga_write_at()`;
* `kprintf(fmt, ...)` — аналог `printf`: разбор формата (`%d`, `%s`, `%x`, `%08x`...) делает функция
  `format()` из `lib.c`, а символы выводятся через `vga_putc`.

> **Почему на экране нет русских букв?** Текстовый режим VGA использует встроенный в видеокарту шрифт
> с кодовой страницей 437 (латиница, псевдографика). Кириллицы в нём нет. Чтобы её показать, нужно
> загрузить в видеокарту свой шрифт — это возможно, но выходит за рамки учебного проекта.

## 4.5. Порты ввода-вывода

Не все устройства доступны через память. У процессоров x86 есть отдельное **пространство портов**
(65536 адресов), к которому обращаются специальными командами `in` и `out`. В C таких команд нет,
поэтому в `ports.h` они обёрнуты в ассемблерные вставки:

```c
static inline void outb(uint16_t port, uint8_t value) {
    __asm__ volatile ("outb %0, %1" : : "a"(value), "Nd"(port));
}
```

Пример — перемещение мигающего курсора (порты видеоконтроллера `0x3D4` / `0x3D5`):

```c
uint16_t pos = cursor_y * 80 + cursor_x;
outb(0x3D4, 0x0F); outb(0x3D5, pos & 0xFF);   // регистр 0x0F — младший байт позиции
outb(0x3D4, 0x0E); outb(0x3D5, pos >> 8);     // регистр 0x0E — старший байт
```

Порты, которые использует MiniOS:

| Порт | Устройство |
|---|---|
| `0x20`, `0x21`, `0xA0`, `0xA1` | контроллеры прерываний PIC |
| `0x40`, `0x43` | системный таймер PIT |
| `0x60`, `0x64` | контроллер клавиатуры (и перезагрузка) |
| `0x70`, `0x71` | CMOS: часы и объём памяти |
| `0x92` | включение линии A20 (в загрузчике) |
| `0x3D4`, `0x3D5` | видеоконтроллер (курсор) |
| `0x604` | выключение питания в QEMU |
