# 3. Реальный и защищённый режим процессора, таблица GDT

Файл: [`boot/boot.asm`](../boot/boot.asm) (вторая половина)

## 3.1. Зачем переходить в защищённый режим

| | Реальный режим (real mode) | Защищённый режим (protected mode) |
|---|---|---|
| Разрядность | 16 бит | 32 бита |
| Доступная память | 1 МБ | 4 ГБ |
| Защита памяти | нет | есть (сегменты, страницы, кольца привилегий) |
| Функции BIOS (`int 0x10`, `int 0x13`) | работают | **не работают** |
| Где используется | первые миллисекунды после включения | все современные 32-битные ОС |

Все современные ОС первым делом уходят из реального режима. 64-битные (Windows, Linux) идут ещё дальше —
в **длинный режим** (long mode), но через защищённый режим всё равно проходят.

Обратите внимание на важное следствие: **после перехода функции BIOS больше недоступны**.
Поэтому загрузчик читает ядро с диска *до* перехода, а в ядре мы пишем собственные драйверы
экрана, клавиатуры и таймера, обращаясь к оборудованию напрямую.

## 3.2. Сегменты и таблица GDT

В защищённом режиме сегментный регистр (`CS`, `DS`, `SS`...) хранит уже не адрес, а **селектор** —
номер записи в таблице **GDT** (Global Descriptor Table). Каждая запись — **дескриптор** длиной 8 байт —
описывает сегмент памяти:

* **база** — с какого адреса начинается сегмент;
* **предел** — какого он размера;
* **права** — код это или данные, можно ли писать, с каким уровнем привилегий можно обращаться.

```
 Логический адрес              GDT                         Физическая память
 ┌─────────┬──────────┐       ┌──────────────────────┐
 │ селектор│ смещение │       │ 0: нулевой дескриптор │
 │  0x08   │ 0x1234   │──┐    │ 1: КОД  база=0 4 ГБ   │◄─ 0x08 / 8 = 1
 └─────────┴──────────┘  │    │ 2: ДАННЫЕ база=0 4 ГБ │
                         │    └──────────────────────┘
                         └─► база (0) + смещение (0x1234) = 0x1234
```

Процессор при каждом обращении к памяти проверяет, что смещение не превышает предел и что права позволяют
операцию. Если нет — возникает исключение **General Protection Fault** (#13). Так ОС защищает память.

### Плоская модель памяти

Сегментация неудобна, поэтому почти все ОС используют **плоскую модель** (flat model):
все сегменты начинаются с адреса 0 и имеют размер 4 ГБ. Тогда логический адрес просто равен
физическому, а защита памяти делается другим механизмом — **страничной адресацией** (paging, см. главу 7).

GDT MiniOS содержит три дескриптора:

| Селектор | Дескриптор | База | Предел | Права |
|---|---|---|---|---|
| `0x00` | нулевой (обязателен по правилам процессора) | — | — | — |
| `0x08` | сегмент кода | 0 | 4 ГБ | выполнение + чтение, кольцо 0 |
| `0x10` | сегмент данных | 0 | 4 ГБ | чтение + запись, кольцо 0 |

Селектор = номер дескриптора × 8 (младшие 3 бита селектора — служебные).

### Разбор байтов дескриптора кода

```nasm
gdt_code:
    dw 0xFFFF       ; предел, биты 0–15
    dw 0x0000       ; база, биты 0–15
    db 0x00         ; база, биты 16–23
    db 10011010b    ; байт доступа
    db 11001111b    ; флаги (старшие 4 бита) + предел, биты 16–19 (младшие 4 бита)
    db 0x00         ; база, биты 24–31
```

Разбросанность полей — наследие процессора 80286, где дескриптор был короче.

**Байт доступа `10011010`:**

| Бит | Значение | Смысл |
|---|---|---|
| 7 (P) | 1 | сегмент присутствует в памяти |
| 6–5 (DPL) | 00 | уровень привилегий 0 (ядро) |
| 4 (S) | 1 | сегмент кода или данных (не системный) |
| 3 (E) | 1 | исполняемый → это код (у сегмента данных 0) |
| 2 (C) | 0 | код не «подчинённый» |
| 1 (R) | 1 | код можно читать (у данных этот бит = «можно писать») |
| 0 (A) | 0 | процессор ставит 1 при обращении |

**Флаги `1100`:** G = 1 (предел считается в блоках по 4 КБ: `0xFFFFF × 4 КБ = 4 ГБ`),
D = 1 (32-битный сегмент).

## 3.3. Кольца привилегий

Защищённый режим вводит **4 уровня привилегий** — «кольца» (rings) от 0 до 3:

```
        ┌───────────────────────────┐
        │  Кольцо 3: программы       │   ← нельзя: cli, hlt, in/out,
        │  ┌─────────────────────┐  │      lgdt, писать в чужую память
        │  │ Кольца 1–2 (не       │  │
        │  │ используются)        │  │
        │  │  ┌──────────────┐   │  │
        │  │  │ Кольцо 0:     │   │  │   ← можно всё
        │  │  │ ЯДРО          │   │  │
        │  │  └──────────────┘   │  │
        │  └─────────────────────┘  │
        └───────────────────────────┘
```

Настоящие ОС запускают программы пользователя в кольце 3: программа с ошибкой (или вирус) не может
отключить прерывания, обратиться к устройству или испортить память ядра — процессор сам это запретит
и вызовет исключение. Тогда ОС просто завершит эту программу, а система продолжит работу.

В MiniOS для простоты **всё работает в кольце 0**, поэтому ошибка в любой команде — например,
деление на ноль командой `crash` — роняет всю систему (kernel panic).

## 3.4. Сам переход

```nasm
    cli                         ; 1. запретить прерывания
    lgdt [gdt_descriptor]       ; 2. сообщить процессору адрес и размер GDT
    mov  eax, cr0
    or   eax, 1                 ; 3. установить бит PE в управляющем регистре CR0
    mov  cr0, eax
    jmp  CODE_SEG:protected_mode_start   ; 4. дальний прыжок
```

1. **Прерывания запрещаются**, потому что таблица прерываний BIOS (IVT) содержит 16-битные обработчики,
   а своей таблицы (IDT) у нас ещё нет. Любое прерывание в этот момент приведёт к сбою.
   Ядро разрешит прерывания само, когда настроит IDT (глава 5).
2. **`lgdt`** принимает 6-байтовую структуру: размер таблицы − 1 и её адрес.
3. **`CR0`** — управляющий регистр процессора. Бит 0 (PE) включает защищённый режим,
   бит 31 (PG) — страничную адресацию (мы её не включаем).
4. **Дальний прыжок** (`jmp селектор:адрес`) загружает в `CS` селектор 32-битного сегмента кода.
   Без него процессор продолжил бы декодировать команды как 16-битные. Заодно очищается
   конвейер процессора, в котором уже лежат заранее прочитанные 16-битные команды.

После прыжка загружаем селектор данных `0x10` во все остальные сегментные регистры —
и мы полноценно в 32-битном мире.
